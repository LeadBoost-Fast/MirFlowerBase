# Mirflowers CRM: полный разбор проекта (для передачи другому ИИ)

Прочитай целиком, код изучать с нуля не нужно. Проверялся только синтаксис (`node --check`). С настоящим Firebase, в браузере и с ИИ не запускалось.

## 1. Что это
CRM-сайт цветочного магазина Mirflowers (Актау): заказы, склад, витрина, клиенты, чаты, график, отчёты, статистика сотрудников, финансы. Владелец хочет продавать систему другим бизнесам. Интерфейс на русском, светлая и тёмная тема, телефон и широкий экран.

Стек: один файл `index.html` (~215 КБ, HTML+CSS+JS, без сборки, шаблонные строки), Firebase compat 10.12.2 (Auth, Firestore, Functions). Проект Firebase: `mirflowersbase`. Cloud Functions на Node 22.

## 2. Файлы
Сайт публикуется через **GitHub Pages** из корня репозитория, сервер (правила и функции) выкладывает **GitHub Actions** (`.github/workflows/deploy.yml`, секрет `FIREBASE_SERVICE_ACCOUNT`). Firebase Hosting не используется. Пошаговый запуск: «Mirflowers CRM: полная инструкция по запуску».

| `manifest.json`, `icon-180.png`, `icon-192.png`, `icon-512.png` | Установка на экран «Домой» |

Все функции в регионе `us-central1` (сайт обращается к `https://us-central1-<проект>.cloudfunctions.net/<имя>`). Ключ ИИ: секрет `ANTHROPIC_API_KEY` в Secret Manager.

Каналы связи: ключи хранятся в `secrets/channels` (`wa:{token,phoneId,verify,secret}`, `ig:{token,verify,secret}`, `tg:{token,secret}`), сайт их только записывает (владелец), читает сервер. Включён ли канал: `settings/main.channels.<wa|ig|tg>.on`. Диалоги: `chats/<канал>_<id>` (WhatsApp: цифры номера, Instagram: IGSID, Telegram: chat id), поле `extId` — кому отвечать. Служебная `waOut/<wamid>` связывает отправленное WhatsApp-сообщение с чатом для статуса «не доставлено».

## 6. Новое в последней версии
### 6.1 Удаление
Кнопка «🗑 Удалить» (`delBtn`, показывается при `own()`, то есть владельцам) с подтверждением и записью в журнал: готовые букеты на витрине и в истории, каталог букетов, позиции склада, история склада, счётчик посетителей, заявки, сделки, карточка клиента (можно удалить и его заказы), диалог целиком, сообщения клиентов, сообщения командного чата, фото/чек/комментарий заказа, отчёты, записи журнала, точки. Логика в `delDoc`, `injDel`, `wrapDel`. В правилах удалять могут `isAdmin() || isOwner()`, остальным удаление запрещено.
«Очистка данных» в Профиле (admin и владельцы): выбор коллекций (массив `WIPE`, функция `wipeCol`), подтверждение словом УДАЛИТЬ.

### 6.2 Статистика (вкладка «Статистика»)
Одна карточка на сотрудника, флорист и оператор объединены («Флорист и оператор»). Считает `stCalc(id,a,b)`: собрано букетов (заказы + коллекция `builds` + витрина), принято заказов, принято оплат, приёмка чужих, взял в работу, возвращено на переделку, доставки, отчёты (чисто/не чисто, проблемы). Периоды: сегодня, 7, 30 дней, месяц (`stRange`, `stp`). Админы и владельцы видят всех и рейтинг, остальные только себя. Заказы считаются по последним 300.
**Сброс:** кнопка «🗑 Сбросить статистику» (admin и владельцы), два подтверждения: `confirm` и ввод слова СБРОС. В `settings/main` пишутся `statsFrom` (мс), `statsFromBy`, `statsFromByName`; `stCalc` считает только после `statsFrom`. Данные не удаляются; кнопка «Показать всю историю» обнуляет `statsFrom`.

### 6.2б Сброс финансов и аналитики
Только владелец и главный админ (`own()`). Кнопка «🗑 Сбросить финансы и аналитику» внизу вкладки «Финансы»: два подтверждения (`confirm`, затем выбор даты и ввод слова СБРОС). В `settings/main` пишутся `finFrom` (дата YYYY-MM-DD), `finFromBy`, `finFromByName`. Функция `fz` в `range()` (Финансы) и `apr()` (Аналитика) не даёт периоду начаться раньше `finFrom`. Данные не удаляются; «Показать всё время» обнуляет `finFrom`. По умолчанию дата = завтра (сегодняшние данные тоже скрываются). «Долги клиентов» по датам не фильтруются. Правила: запись в settings у владельцев и так полная, менять не нужно.

### 6.2в Резервная копия и экспорт
Профиль, блок «Резервная копия и экспорт» (`expCard`, admin и владельцы). «💾 Резервная копия (JSON)»: выбор коллекций (`EXPC`), опция «без фото», скачивается один файл `mirflowers-backup-ДАТА.json` (Timestamp превращаются в `{ts:мс}`, чаты идут вместе с сообщениями). CSV для Excel (разделитель `;`, UTF-8 с BOM): заказы (все, не только последние 300), клиенты, расходы (только владельцы). Расходы и закупочные цены в копию попадают только у владельцев. Действия пишутся в журнал. Автокопия по расписанию описана в 6.5.

### 6.2г Push-уведомления (когда сайт закрыт)
Технология: Firebase Cloud Messaging (веб-push). Файлы: `public/firebase-messaging-sw.js` (сервис-воркер, показывает уведомление из data-сообщения), `public/manifest.json` и иконки `icon-180/192/512.png` (для установки на экран «Домой», на iPhone push работают только так, iOS 16.4+), `firebase.json` (заголовок no-cache для сервис-воркера).
Клиент (`index.html`, блок «Push-уведомления»): карточка «Push на телефон» в Профиле (`pushCard`): включить/выключить, выбор типов (`PUSHEV`: ord, ready, courier, lead, chat, rep, remind), «Прислать проверку». Токен устройства хранится в `pushTokens/{токен}`: `uid`, `role`, `ev{тип:false}`, `ua`, `ts`. Ключ VAPID вставляет владелец в той же карточке (`settings/main.vapid`). При выходе токен удаляется, при входе другого пользователя токен переходит к нему (`pushSync`).
Сервер (`functions/index.js`): `pushNewOrder` (новый заказ), `pushOrderChange` (готов к приёмке, переделка, назначена доставка), `pushNewLead`, `pushClientMsg` (входящее сообщение клиента), `pushNewReport` (админам и владельцам), `pushReportReminder` (каждый день 20:00 Asia/Aqtau тем, кто по графику работал и не сдал отчёт), `pushTest`. Общая функция `push(type,who,msg,exclude)` выбирает токены по роли и настройкам, автору действия не шлёт, мёртвые токены удаляет. Если при деплое ошибка региона, задайте `OPT={region:"..."}` по региону Firestore.
Правила: `pushTokens`: сотрудник читает, создаёт, меняет и удаляет только свои токены (`uid == request.auth.uid`).
Деплой: `firebase deploy --only hosting,firestore:rules,functions` (нужен тариф Blaze; Cloud Scheduler включится сам). Старые уведомления внутри открытого сайта (`nf*`, `np_*`) остались и работают отдельно.

### 6.3 Отчёты (вкладка «Отчёты», карточка на главной)
Типы (`RPT`) и кто сдаёт (`RPW`): `show` «Витрина: свежесть» (помощник, флорист, оператор, админ), `desk` «Рабочее место» (чисто/не чисто, при «не чисто» обязателен комментарий, ИИ фото не оценивает), `op` «Смена оператора» (чек-лист `OPCK`, касса, снимок дня `mySnap`).
Проверка: админы и владельцы принимают (`rp_ok`) или пишут замечание, видят блок «Сегодня не сдали отчёт» (`rpMissing`: по графику `shifts` с `t:"work"` и ролям assistant/florist/operator) и фильтр «⚠ Проблемы». Флаги `rpFlag`: ok / warn / bad.

### 6.4 Шаблоны
`settings/main.tpls` = массив `{n,t}`, 8 стандартных (`DEFTPL`). Редактируют все, кроме florist и assistant (`canTpl()`); в правилах admin, operator, courier могут менять только `tpls` и `updatedAt`.

### 6.5 Остатки, накладная с QR, статус для клиента, автокопия (итог)
**Работает без тарифа Blaze (Firestore + Hosting/GitHub Pages):**
- **Накладная с QR:** «🖨 Накладная» в карточке заказа (`o_print`), печать A5. QR ведёт на страницу статуса. Библиотека qrcode-generator 1.4.4 (cdnjs); без интернета печатается без QR.
- **Статус для клиента:** «🔗 Ссылка клиенту» (`o_link`). В заказ пишется `pub` (24 hex, случайный), в коллекцию `pubOrders/{pub}` копируются только `bn, st, dv, date, time, shop, phone`. Ссылка: `status.html?t=<pub>` (работает на любом статическом хостинге). Синхронизацию делает открытый сайт сотрудника (`pubAuto` после снимка заказов, поле `pubKey` на заказе); курьер не пишет в `pubOrders`, статус «Выдан» подтянется, когда сайт откроет сотрудник. Правила: `pubOrders` читается по `get` кому угодно, `list` запрещён, писать `isWork()`. «Повторить» заказ `pub`/`pubKey` не копирует. При удалении заказа документ `pubOrders` остаётся (удалить вручную).
- Остатки: поле «минимум» и пометка «Мало» в «Складе» уже были.
**Написано, но не включено (нужен тариф Blaze, Storage, `firebase deploy --only functions`):** в `functions/index.js` `pushLowStock` (push `stock`, включается в Профиле), `dailyBackup` (каждый день 03:00 Asia/Aqtau, JSON в Cloud Storage `backups/ГГГГ-ММ-ДД/`, 14 дней, статус `settings/main.lastBackup`, показывает `bkInfo()`), `backupNow` (кнопку `data-a="bk_now"` в `expCard` нужно вернуть, обработчик в коде есть), `orderStatus` (HTTP-вариант статуса, не используется). Пока ручная резервная копия JSON/CSV в Профиле.

### 6.6 Правки интерфейса (ноябрь 2026)
- **Окна:** у каждого модального окна есть ручка и крестик ✕, закрытие свайпом вниз (телефон) и клавишей Esc (`modal()`, `swipeClose()`).
- **Накладная:** открывается поверх страницы (`#wb`), кнопки «Закрыть» и «Печать», размеры A5, чек 80 мм, этикетка 58 мм (запоминается в `localStorage.wbsz`).
- **Заказ:** поле «Время получения клиентом» (`time`) и новое «Флористу: сделать до» (`mk`, datetime-local). Карточка показывает «Клиенту: дата время» и плашку «Сделать до …» (красная, если просрочено). Главная флориста начинается со списка «Заказы к сборке», отсортированного по `mk`; новые заказы там принимаются кнопкой «На себя / в работу».
- **Витрина:** вместо чипа «Каталог букетов» кнопка «＋ Добавить букет» (вручную, из каталога, с необязательным списанием со склада). «Продать» показывает сумму и учитывает продажу в главной (сумма и число продаж за сегодня) и в «Финансах».
- **Склад:** плитка «Стоимость склада» (только владелец и главный админ) показывает «—» и подсказку, пока не заданы закупочные цены.
- **Владелец и главный админ:** числа на главной (`data-go`) открывают «Финансы» или «Статистику» и прокручивают к нужной строке с подсветкой.
- **Точка:** при входе окно «Где вы сегодня?» (`#locgate`, `locGate()`). Выбор хранится в `localStorage.locSel` и сбрасывается в конце смены по графику (`locUntil()`), без смены в графике через 12 часов. «Все точки» могут выбрать только администраторы. У сотрудников с закреплённой точкой окна нет.

### 6.8 Карта, переходы, выбор точки (6 ноября 2026)
- **2ГИС для курьера:** кнопка «🗺 2ГИС» (`gisBtn`, `gis`) в карточках заказов, в окне заказа и на вкладке «Курьер» открывает поиск адреса в 2ГИС (Актау). Встроенной карты нет: для неё нужен API-ключ 2ГИС.
- **Переходы:** строки блока «Уведомления» на главной кликабельны (`data-a="al"`, фильтр `fz2` для просроченных и неоплаченных). Плитки склада открывают разбор: позиции, «Заканчивается», «Стоимость склада» (остаток × закупка, доли, по точкам).
- **Push:** сервер передаёт ссылку (`/?o=ID`, `/?tab=...`), сервис-воркер открывает нужный заказ или вкладку (`openLink`).
- **Точка:** у окна «Где вы сегодня?» не было CSS (оно показывалось внизу страницы), добавлен `#locgate`. Владельцу и главному админу окно не показывается. Изменить точку: Профиль, «Где я работаю сегодня» (`lc_re`).
- **Скорость:** перерисовка 30 мс, автоопределение long polling Firestore, переподключение при возврате на вкладку и появлении сети.

## 7. Модель данных Firestore
- `orders/{id}`: client, phone, bn, comp, p, pre, fee, cpay, date, time, dv, addr, courier, src, pay, paid, pub, mk, st, by, ts, img, proof, needPhoto, takenBy, takenAt, asm, readyAt, rv, rimg, accBy, accAt, redoN/At/By/Note, cm[], photoSent, paidAt, paidBy, chk, chkBy, chkAt, sc.
- `builds/{id}`: name, bid, show, loc, by, byName, ts (сборка каталога; создаётся в `build`).
- `reports/{id}`: type, by, byName, role, loc, date, ts, photos[], note, rv ("" | "ok" | "bad"), rvNote, rvBy, rvByName, rvAt; show: fr, fo, wo, tidy, fresh; desk: cl; op: ck[], cash, snap{made,fl,paid}.
- `chats/{канал_телефон|ник}` (+ `msgs/{id}`), `team`, `presence/{uid}`, `staff/{uid}` (active, role, email, name, loc, createdAt), `settings/main` (name, addr, phone, hours, fx{rvOn,photoDef,photoAuto,payOne,teamChat,clientChat}, photoMsg, tpls[], channels{}, statsFrom, statsFromBy, statsFromByName, finFrom, finFromBy, finFromByName), `inventory`, `invcost` (закупка, только владельцы), `stockMovements`, `bouquets`, `showcase`, `visits`, `customers`, `leads`, `deals`, `expenses`, `shifts` (uid, date, t), `locations`, `activityLogs`.

## 8. Правила Firestore (кратко)
Функции: `isActive`, `isOwner` (по email), `isAdmin`, `isMgr`/`isWork`, `isOpRole`, `isCourier`.
- `staff`: владельцы всё; обычный админ управляет не-админами и не трогает владельцев.
- `orders`: оплата, приёмка и переделка (`paid*`, `acc*`, `redo*`) только admin, operator, florist; курьер меняет только свои доставки и чек; удаление admin/владельцы.
- `builds`, `reports`: читают админы и владельцы всё, остальные только свои (`by == uid`); создают только от своего имени; `reports` правят админы и владельцы; `builds` не правятся.
- `invcost`, `expenses`, `locations`: только владельцы (locations читают все активные).
- `settings`: владельцы всё; admin/operator/courier только `tpls`; admin ещё поля сброса статистики.
- Везде удаление только `isAdmin() || isOwner()`.
Запросы сайта подогнаны под правила: сотрудники запрашивают `builds` и `reports` с `where("by","==",uid)`.

## 9. Cloud Functions
(push-функции описаны в 6.2г)
- `deleteStaff` — удаляет аккаунт Auth, профиль, presence и смены. Админы не трогают админов и владельцев.
- `setStaffPassword` — смена пароля сотрудника (от 6 символов). Без функций пароль меняется письмом сброса.
- `aiReply` — черновик ответа клиенту (модель `claude-haiku-5-5`, секрет `ANTHROPIC_API_KEY`), доступ admin/operator/florist, отправляет человек.

## 10. Чего нет и ограничения
1. Нет серверной части каналов: WhatsApp, Instagram, Telegram не подключены (нужен webhook; сначала Telegram-бот, потом WhatsApp Cloud API, потом Instagram; у 2ГИС нет API ответов).
2. Закон РК о персональных данных: Firebase без региона в РК. Для продажи другим бизнесам планировался VPS в Казахстане (Node.js, PostgreSQL); работу с базой стоит вынести в один модуль.
3. Нет мультиарендности (`orgId`, изоляция в правилах, тарифы).
4. Фото хранятся base64 в документах (лимит 1 МБ), заказы считаются по последним 300, оформление и уведомления только на устройстве, запрет принять свой заказ только в интерфейсе.
5. Кнопки удаления в интерфейсе видят только владельцы, хотя правила разрешают и админам.
6. Не тестировалось в браузере с настоящим Firebase. Нужен прогон по всем ролям.
7. Старые сборки каталога без витрины в статистику не попадают, считается с момента добавления `builds`.
