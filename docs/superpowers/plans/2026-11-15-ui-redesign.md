# Новый вид и удобство сайта: план реализации

> **Для исполнителя:** использовать superpowers:executing-plans (выбрано владельцем неявно: он поручил сделать самому, решение «своими силами в этой сессии»). Шаги отмечены флажками.

**Цель:** упростить интерфейс, дать расстановку главной как HUD (хранится на сервере, задаётся по ролям) и «Живую картину» для админов, не ломая функции и данные.

**Архитектура:** исходники в `src/app.js` (один файл, сборка `node build/build.mjs`), новые виджеты и «Живая картина» добавляются там же отдельными блоками кода по образцу `HB` и `ROLE`. Расстановка в Firestore (коллекция `layouts`). Правила в `firestore.rules`, проверки в `tests/site.cjs` и `tests/walk.cjs` на эмуляторах.

**Технологии:** Firebase compat 12.19.0 (Firestore, Auth), esbuild (сборка), Playwright (проверки), чистый JS без фреймворков.

**Спек:** `docs/superpowers/specs/2026-11-15-ui-redesign-design.md`

## Общие ограничения
- Работающие функции, данные и права не менять; все проверки (сейчас 166 в `tests/site.cjs` + обход `tests/walk.cjs`, 138 экранов) остаются зелёными после каждой задачи.
- Правка только в `src/`, затем `node build/build.mjs`; перед коммитом `node build/build.mjs --check`; после изменения `src/d-*.js` менять `DSG_V` в `src/index.template.html` и `src/app.js` (сейчас `20261116j`).
- Тексты интерфейса простые, на русском, без эмодзи; новые строки добавлять в казахский словарь `src/d-kk.js`.
- Проверки запускать на чистых эмуляторах (`pkill` эмуляторов, запуск заново), результат в конце вывода: «OK» и «ERRS 0».
- Расстановка из «Мой экран» в памяти телефона (`myscr:<uid>`) не теряется: переносится один раз.
- Слежки не добавлять: только то, что уже пишется (заказы, журнал, присутствие, смены).

## Review Focus
1. Человек без сохранённой расстановки и без интернета: главная показывает встроенный набор (`ROLE.home`), не пустой экран.
2. Расстановка содержит виджет, которого уже нет (удалили из кода): пропускается без ошибки.
3. Владелец убирает у роли виджет, который сотрудник уже поставил: у сотрудника он исчезает, ничего не падает.
4. Сотрудник пытается записать расстановку другому сотруднику (правила): отказ.
5. Заказ без части отметок времени (нет `takenAt`, `readyAt`): лента дня рисуется полосой до последнего известного этапа, без «NaN».
