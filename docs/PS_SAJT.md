# Сайт на сервере PS.kz: первая выкладка

Что это. Первый шаг переезда: сайт (страницы и скрипты) начинает раздаваться с вашего сервера PS.kz. **База, вход, фото и уведомления пока остаются в Firebase** (Google), пока не готово ядро своего сервера (этап 1, см. `docs/PLAN_VPS_KZ.md`). Закон о хранении персональных данных этим шагом не закрывается: он закрывается, когда база переедет. Зато сервер, домен, выкладка и копии будут уже настроены и проверены.

Для чего он нужен: проверить сервер, домен и выкладку заранее, чтобы на этапе 1 не тратить время на подготовку.

## Что подготовлено в репозитории
- `tools/make-site.mjs`: собирает папку `dist/ps-site/site` только с нужными магазину файлами (проверяет, что все файлы на месте). Запуск: `node tools/make-site.mjs`.
- `server/Caddyfile`: раздаёт папку по HTTPS, долго хранит файлы с хэшем, страницы и настройки проверяет при каждом открытии, адрес `/health` отвечает `ok`.
- `.github/workflows/deploy-ps.yml`: при каждом слиянии в `main` кладёт свежий сайт на сервер. Пока секреты не заданы, работа пропускается и ничего не ломает.
- `server/setup.sh`, `server/docker-compose.yml`: подготовка сервера (защита, Docker, папки).
- Проверка папки сайта идёт в GitHub вместе с остальными проверками.

Что не проверено: `Caddyfile` и скрипты я не запускал на живом сервере и в Caddy (в этой среде его нет). Первый запуск делаем вместе: сначала `caddy validate`, потом старт.

## Шаги после заказа сервера (25 ноября)
1. Заказать VPS Basic-3 в PS.kz (`docs/PS_KZ_INSTRUKCIYA.md`), добавить SSH-ключ.
2. Домен. Для HTTPS и для работы сайта на iPhone нужен адрес, который указывает на сервер. Варианты: свой `.kz` (платно) или поддомен уже имеющегося домена. Без домена получить сертификат нельзя.
3. На сервере: `bash setup.sh`, заполнить `/opt/crm/.env` (домен, пароль базы), затем `docker compose up -d`. Базу из `docker-compose.yml` можно пока не запускать, она нужна с этапа 1.
4. Создать отдельный SSH-ключ только для выкладки. Открытый ключ добавить на сервер, закрытый записать в секреты GitHub: `PS_SSH_KEY`, а также `PS_HOST` и `PS_USER`. Пароли и ключи в чат не отправлять.
5. Запустить выкладку: GitHub, Actions, «Выкладка сайта на сервер PS.kz», Run workflow. Открыть `https://ваш-домен/health` (ответ `ok`) и сам сайт.
6. В Firebase Console, Authentication, Settings, Authorized domains: добавить новый домен. Без этого вход на новом адресе не пройдёт.

## Что изменится для людей при переходе на новый адрес
Новый адрес для телефона это новый сайт:
- Все сотрудники входят заново.
- Иконку на экране «Домой» нужно поставить заново.
- Уведомления нужно разрешить заново (они привязаны к адресу).
- Настройки вида (дизайн, «Мой экран», язык) хранятся на телефоне и пропадут, их нужно выбрать заново.
Поэтому переходим один раз, заранее предупредив сотрудников. Лучше сразу на тот адрес, который останется после полного переезда.

## Откат
Старый сайт на GitHub Pages остаётся рабочим. Если с новым что-то не так, сотрудники продолжают пользоваться старым адресом: база общая.
