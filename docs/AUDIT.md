## ⚠️ Замечания и слабые места

**Архитектура**
- **Один файл ~680 КБ** (HTML + CSS + JS + казахский словарь). Телефон при каждом обновлении сайта скачивает и разбирает всё целиком; кэшировать части по отдельности нельзя.
- **57 отдельных обработчиков `click` на `document`.** Каждый клик проходит через все 57 проверок `closest()`. Работает, но логика «кнопка → действие» разбросана по файлу.
- **62 пустых `catch(e){}`** — ошибки молча проглатываются, сложнее находить причины сбоев.
- **408 inline-стилей и 77 `!important`** — дизайны перебивают друг друга через `!important`; новые правки стилей приходится «пробивать» выше.
- **Без ограничений грузятся** `customers`, `deals`, `leads`, `expenses`, `presence` — сейчас они маленькие, но растут.
- **Почты владельцев зашиты в код** (`TOP` на сервере, `isOwnEm` на сайте) — смена владельца требует правки кода.

**Интерфейс (UX/UI)**
- **31 `confirm()` и 9 `prompt()`** — системные окна iPhone выглядят чужеродно на фоне окон сайта и не поддерживают оформление.
- **Шесть старых дизайнов** дублируют одну информацию разными графиками (кольца, столбики, пончик) — на главной владельца одни и те же цифры показаны 2–3 раза.
- Поле времени и выбор файла рисует сам iPhone (на английском телефоне — «Choose File», «11:00 PM») — сайт не может это изменить.

## 🛠 Рекомендации (best practices)

1. **Разделить файл**: `app.css`, `app.js`, `kz.js` (словарь подгружать только при казахском языке) + service worker с кэшем. Ожидаемо: повторный запуск в 3–5 раз быстрее на слабых телефонах.
2. **Один маршрутизатор действий** вместо 57 обработчиков: `ACT = {"det": id => detail(id), "s_mi": …}` и один `click` по `[data-a]`.
3. **Ошибки не глотать**: вместо `catch(e){}` — `catch(e){logErr(e)}` с записью в журнал (раздел «Связь с базой» уже есть).
4. **Ограничить остальные подписки** по дате/статусу, как сделано для витрины.
5. **Свои окна подтверждения** вместо `confirm()/prompt()` — в стиле сайта, с крупными кнопками.
6. **Роли владельца — в базе** (`staff.role = "owner"`), а не почтами в коде.
7. **Дизайны — через токены**: общие переменные (радиус, тень, шрифт, отступы) вместо копий правил с `!important`.
