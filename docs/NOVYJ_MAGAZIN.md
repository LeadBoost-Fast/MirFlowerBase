# Новый магазин: пошагово (вариант «копия на магазин»)

Пока нет своего сервера, каждый магазин получает свой проект Firebase и свою выкладку. Данные магазинов не смешиваются. Я подготовил генератор: он собирает сайт, правила и функции с настройками магазина. От вас нужны только действия в консолях Firebase и GitHub (я их не вижу и не должен видеть).

## Шаг 0. Что узнать у магазина
Название, город, почта владельца (с неё он войдёт), телефон, реквизиты (ИП или ТОО, БИН, адрес), ссылки Instagram и 2ГИС.

## Шаг 1. Проект Firebase магазина (на почте магазина, 15 минут)
1. console.firebase.google.com, «Добавить проект», название магазина, Google Analytics отключить.
2. Перевести проект на тариф **Blaze** (нужна карта магазина; для сообщений WhatsApp и push функции обязательны, при малом объёме счёт почти нулевой).
3. «Authentication», «Способ входа», включить «Электронная почта и пароль». Во вкладке «Пользователи» нажать «Добавить пользователя»: почта владельца и временный пароль (владелец потом нажмёт «Забыли пароль» и задаст свой).
4. «Firestore Database», «Создать базу», режим «Рабочий», регион выбрать ближайший (Казахстана в списке нет).
5. «Storage», «Начать» (для фото).
6. «Hosting», «Начать» (достаточно нажать далее до конца).
7. «Настройки проекта», «Ваши приложения», значок «</>» (веб), назвать как магазин, **скопировать блок firebaseConfig целиком в текстовый файл**, например `fb.txt`.
8. «Настройки проекта», «Cloud Messaging», «Веб-конфигурация», «Сгенерировать пару ключей»: скопировать открытый ключ (он понадобится в настройках уведомлений).
9. «Настройки проекта», «Учётные записи служб», «Создать новый закрытый ключ». Скачается файл `.json`. **Он даёт полный доступ к проекту: никому не пересылайте, мне тоже.**

## Шаг 2. Секрет в GitHub (вы, 2 минуты)
Репозиторий на GitHub, Settings, Secrets and variables, Actions, «New repository secret».
Имя: `FIREBASE_SA_` + название магазина заглавными, например `FIREBASE_SA_ALMATY1`. Значение: весь текст из файла `.json`. Файл после этого удалите с телефона и из загрузок.

## Шаг 3. Создание магазина (я)
Мне нужны: файл `fb.txt` (там только публичные настройки веб-приложения, его можно прислать), название папки магазина (латиница, например almaty1), название, город, почта владельца. Я выполняю:

```
node tools/new-shop.mjs create almaty1 --name "Название" --city "Алматы" --gis almaty --owner почта --fb fb.txt
node tools/new-shop.mjs bundle almaty1     # проверка, что пакет собирается
```
и заполняю реквизиты (`legal`) в `shops/almaty1/shop.config.js`. Иконки магазина кладу в ту же папку.

## Шаг 4. Выкладка (вы или я)
GitHub, Actions, «Deploy shop», «Run workflow», в поле shop написать `almaty1`. Через 3–5 минут сайт доступен по адресу `https://<проект>.web.app`.

## Шаг 5. Первый вход владельца
Владелец открывает адрес, входит по почте и временному паролю, открывается мастер настройки (название, шаблон, доставка). В «Настройки, Уведомления» вставляет открытый ключ из шага 1.8. Дальше подключаем WhatsApp и Instagram (`docs/META_WHATSAPP.md`).

## Что обновлять потом
Когда сайт меняется, для каждого магазина снова запускается «Deploy shop». Поэтому при 5–6 магазинах это неудобно: именно для этого нужен единый сервер (Этап 1).
